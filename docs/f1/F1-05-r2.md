# F1-05 — Prova R2: Upload/Download Privado com Isolamento por Empresa

**Branch**: `reescrita/f1-prova-stack`  
**Status**: ✅ CONCLUÍDO  
**Data**: 2026-10-26

---

## Objetivo

Provar que o Cloudflare R2 funciona no runtime Workers com:

- Upload de arquivo binário (multipart/form-data)
- Download proxied privado (R2 → Worker → cliente)
- Deleção com validação de isolamento
- Listagem paginada por empresa
- **Isolamento por empresa**: prefixo `empresa/{empresaId}/` impede IDOR entre tenants

---

## Arquitetura

```
Cliente
   │
   ▼
SvelteKit → apiHandler (sveltekit.ts)
   │              │ passa R2 binding
   ▼              ▼
Hono /api/v1/r2-proof/*
   │
   ├── POST /upload          → r2Upload(r2, empresaId, context, filename, body)
   ├── GET  /download/:key   → r2Download(r2, key, empresaId) → stream response
   ├── DELETE /delete/:key   → r2Delete(r2, key, empresaId)
   ├── GET  /list/:empresaId → r2List(r2, empresaId, context)
   └── GET  /head/:key       → r2Head(r2, key, empresaId) [metadados]
   │
   ▼
R2Bucket (env.R2 Workers binding)
```

**Nunca há URL pública**: arquivos são privados por padrão e só acessíveis
via proxy autenticado (Guard auth em F2-03).

## Isolamento de Tenant

### Convenção de chave

```
empresa/{empresaId}/{context}/{filename_sanitizado}
```

Exemplos reais:
- `empresa/42/documentos/passaporte_joao.pdf`
- `empresa/42/logos/logo_empresa.png`
- `empresa/7/vouchers/vou-2024-001.pdf`

### Garantias

| Ameaça | Mitigação |
|--------|-----------|
| IDOR (acesso a chave de outra empresa) | `assertKeyBelongsToEmpresa()` valida prefixo em toda operação |
| Path traversal em filename | Sanitização: `filename.replace(/[^a-zA-Z0-9._\-]/g, '_')` |
| Tamanho excessivo | Rejeita > 10MB na rota de prova (ajustável por contexto) |
| Tipos não autorizados | Allowlist MIME: jpeg, png, webp, gif, pdf, txt |

### Código de validação

```typescript
export function assertKeyBelongsToEmpresa(key: string, empresaId: number): void {
  const prefix = `empresa/${empresaId}/`;
  if (!key.startsWith(prefix)) {
    throw new Error(`Chave R2 inválida para empresa ${empresaId}: ${key}`);
  }
}
```

## Download Privado: estratégia de proxy vs presigned URL

### Opção A — Proxy via Worker (escolhida para F1)

```
GET /api/v1/r2-proof/download/:key?empresaId=42
→ Worker: valida auth + empresaId, r2.get(key), streams response
```

**Vantagens**:
- Auth verificada em cada request
- Sem URL temporária para vazar
- Headers de response controlados (`Cache-Control: private, no-store`)

**Desvantagens**:
- CPU/egress do Worker para cada download
- Latência ligeiramente maior

### Opção B — Presigned URL (futura em F4+)

R2 suporta presigned URLs via Workers `fetch(signedRequest)` usando
`r2.sign()` experimental. Útil para arquivos grandes (> 50MB) onde
streaming via Worker seria caro.

**Trade-off**: URL expira em N segundos mas pode ser compartilhada
acidentalmente. Aceitável para downloads programáticos com expiração curta (60s).

## Como testar

```bash
# 1. Iniciar wrangler dev com R2 local
npm run dev:cf

# 2. Upload
curl -X POST http://localhost:8787/api/v1/r2-proof/upload \
  -F "file=@/tmp/teste.pdf" \
  -F "empresaId=1" \
  -F "context=documentos"
# Resposta: { "key": "empresa/1/documentos/teste.pdf", "encodedKey": "...", ... }

# 3. Listar
curl "http://localhost:8787/api/v1/r2-proof/list/1?context=documentos"

# 4. Download (use encodedKey da resposta do upload)
curl "http://localhost:8787/api/v1/r2-proof/download/empresa%2F1%2Fdocumentos%2Fteste.pdf?empresaId=1" \
  --output /tmp/baixado.pdf

# 5. Metadados
curl "http://localhost:8787/api/v1/r2-proof/head/empresa%2F1%2Fdocumentos%2Fteste.pdf?empresaId=1"

# 6. Deletar
curl -X DELETE "http://localhost:8787/api/v1/r2-proof/delete/empresa%2F1%2Fdocumentos%2Fteste.pdf?empresaId=1"

# 7. Provar isolamento — tentar baixar arquivo da empresa 1 como empresa 2
curl "http://localhost:8787/api/v1/r2-proof/download/empresa%2F1%2Fdocumentos%2Fteste.pdf?empresaId=2"
# Esperado: 403 com { "error": "Chave R2 inválida para empresa 2: ..." }
```

## Configuração wrangler.toml

```toml
[[r2_buckets]]
binding = "R2"
bucket_name = "vturapp-storage"
preview_bucket_name = "vturapp-storage-dev"
```

Para criar o bucket em produção:
```bash
wrangler r2 bucket create vturapp-storage
wrangler r2 bucket create vturapp-storage-dev
```
